## Reachability and protection verification

- A fresh Vite in-memory production graph (`write:false`) includes none of the eight advisory packages in client chunks. Importing the compiled server module loads only **qs** among them. Source review finds no vulnerable-package invocation in non-test app/server code; production entry executes compiled Express, never a Vite/Vitest/CLI server. This is source/graph evidence, not a live production trace.
- Installed Express 5.2.1 sets `query parser` to `simple` in `node_modules/express/lib/application.js`; `server/app.ts` does not override it. A bounded probe replaced qs.parse/stringify with throwing counters and fed bracket/comma/constructor-shaped input through the actual configured parser: flat keys, zero qs calls. No `express.urlencoded` middleware or extended parser exists in application code. API query objects are validated by the result/leaderboard stores. Neither qs advisory's prerequisite path is exercised.
- `server/app.ts`: exact token-origin allowlist before CORS reflection; JSON-only token POST, 8 KB limit, no inflation, exact body shape/code pattern. Session and attempt routes independently enforce their own origin/request/CSRF/cookie checks before body handling; 4 KB session and 68 KB attempt bodies with inflation disabled. Leaderboards reject unexpected body transport and validate queries. CORS is not treated as authentication or a defense against arbitrary non-browser requests.
- Token/session/attempt/leaderboard routes have bounded per-socket/global limiters and pending caps of **20/10/4/4**; global windows cap at 600/minute per router, with bounded key storage. `server/index.ts`: 10-second request/header/socket timeouts, 5-second keepalive, 16 KB maximum headers. Discord exchange has an 8-second abort timeout and fixed upstream with redirects rejected; database statement/query deadlines remain bounded. Timeouts/rate limits are defense in depth, **not** credited with interrupting synchronous infinite loops or making a reachable parser vulnerability safe.
- Production static serving uses `server/artifacts.ts` manifest/hash validation and `server/app.ts` path checks, denies dot paths/traversal, source/server/build/docs/node_modules/scripts and unlisted asset/file routes, and serves only verified files or the HTML shell. No directory/file upload or runtime stylesheet processing endpoint exists.
- Safe errors omit stack/upstream payload/driver details; logs use fixed events and public release metadata. Build inputs use an explicit public client allowlist; secret-bearing configuration stays backend-only, .env is ignored/untracked, and the production entry does not load dotenv. No secret values were read for this assessment.
- **115 focused security/request-boundary tests across five files passed**: app, production, sessions, attempts and guild routes. They cover validation, origins, method/body bounds, authentication, limits, sanitized failures, static artifacts and shutdown/upstream behavior as applicable. No exhaustive gameplay/browser matrix, production database query or native iPhone test was rerun.
